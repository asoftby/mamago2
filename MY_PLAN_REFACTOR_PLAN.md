# Переработка "Моего плана" - от слотов к хронологическому плану

## AUDIT SUMMARY

### Текущая архитектура (СТАРАЯ)
- **UI**: 3 фиксированных слота (Утро/День/Вечер)
- **State**: `PlanSlot[]` с типом слота и рекомендациями
- **Logic**: Recommendation engine, привязанный к слотам
- **Data**: `PlanItemWithActivity` с `startsAt`, но логика игнорирует время

### Новая архитектура (НОВАЯ)
- **UI**: Хронологический список событий на дату
- **State**: `PlanItem[]` отсортированные по времени
- **Logic**: Простое добавление/удаление без рекомендаций
- **Data**: `PlanItemWithActivity` с `startsAt` как основной сортировочный ключ

## НОВАЯ ДОМЕННАЯ МОДЕЛЬ

```typescript
// Новый интерфейс для плана
interface ChronologicalPlan {
  date: string;           // ISO date
  items: PlanItem[];      // отсортированы по startsAt
}

interface PlanItem {
  id: string;
  date: string;
  activityId: string | null;
  title: string;
  startsAt: Date | null;  // основной ключ сортировки
  endsAt?: Date | null;
  activity?: Activity;
  // metadata
  createdAt: Date;
  updatedAt: Date;
}

// Группировка для UI
interface PlanItemGroup {
  timeLabel: string;      // "10:00" или "В течение дня"
  items: PlanItem[];
}
```

## EDGE CASES

1. ✅ Несколько событий в один день с разным временем - сортировка по startsAt
2. ✅ Два события в одно и то же время - сохранять порядок добавления (createdAt)
3. ✅ Событие без времени - группа "В течение дня" в конце
4. ✅ Событие с несколькими сеансами - пользователь выбирает конкретный при добавлении
5. ✅ Пустой день - empty state с CTA
6. ✅ Удаление элемента - пересчет индексов (не нужно, т.к. используем id)
7. ✅ Сортировка после добавления - автоматическая через useMemo
8. ✅ Старые plan items - миграция не требуется, просто игнорируем slotType

## UX ЛОГИКА

### Добавление события
1. Пользователь нажимает "Добавить" или "Найти еще"
2. Переходит на страницу поиска с контекстом даты и персон
3. Выбирает событие
4. Если у события есть время - автоматически добавляется в нужное место
5. Если времени нет - предлагаем выбрать ориентировочное время (MVP вариант 1)

### Отображение
- Дата в заголовке
- Список событий в хронологическом порядке
- Каждое событие: время + название + адрес + цена + действие
- Empty state если пусто
- CTA "Найти еще" внизу

### Действия с событием
- Открыть карточку (детали)
- Удалить из плана
- (Опционально) Заменить / изменить время
