# Исправление сохранения черновика маршрута

## Проблема

При попытке сохранить черновик маршрута на первом шаге создания (где еще нет остановок), пользователь получал ошибку:

```
at least 2 stops required
```

Это происходило потому, что API требовал минимум 2 остановки для любого маршрута, включая черновики.

## Решение

### 1. Изменения в API (`src/app/api/routes/route.ts`)

**До:**
```typescript
if (!stops || stops.length < 2) {
  return NextResponse.json({ error: "at least 2 stops required" }, { status: 400 });
}
```

**После:**
```typescript
// Для публикации требуем минимум 2 остановки, для черновика можно без них
if (publish && (!stops || stops.length < 2)) {
  return NextResponse.json(
    { error: "at least 2 stops required" },
    { status: 400 },
  );
}
```

**Что изменилось:**
- Валидация на минимум 2 остановки теперь применяется **только при публикации** (`publish === true`)
- Черновики (`publish === false`) можно сохранять с любым количеством остановок, включая 0

### 2. Улучшение обработки ошибок на клиенте (`CreateRouteWizard.tsx`)

Добавлена клиентская валидация с понятными сообщениями:

```typescript
// Проверяем название
if (!state.title.trim()) {
  toast.error("Укажите название маршрута");
  setSaving(false);
  return;
}

// Дополнительная проверка для публикации
if (publish && validStops.length < 2) {
  toast.error("Для публикации нужно минимум 2 остановки", {
    description: "Добавьте ещё остановки или сохраните как черновик",
  });
  setSaving(false);
  return;
}
```

**Преимущества:**
- Пользователь получает понятное сообщение до отправки запроса
- Подсказка о том, что можно сохранить как черновик
- Более понятный перевод ошибки с сервера

### 3. Исправление меню профиля

Добавлен недостающий обработчик `onGoToPersonalRoutes` в:
- `src/lib/account/accountMenuBuilders.ts` - деструктуризация параметра
- `src/lib/account/accountMenuBuilders.ts` - параметры `buildBusinessAccountModel`
- `src/app/(ui)/ui-lab/_sections/AccountDropdownSection.tsx` - тестовые данные

### 5. Поддержка множественной загрузки фото

Добавлена возможность выбирать **несколько фотографий одновременно** при загрузке изображений для точек маршрута.

**Проблема 1:** Можно было выбрать только 1 файл за раз  
**Решение:** Добавлен атрибут `multiple` в input

**Проблема 2:** При выборе нескольких файлов сохранялось только последнее фото  
**Причина:** Race condition при обновлении состояния  
**Решение:** Batch callbacks (`onAddBatch`) для атомарного добавления всех изображений

**До:**
- Можно было выбрать только 1 файл за раз
- Для добавления 5 фото нужно было 5 раз нажать кнопку загрузки

**После:**
```typescript
// ImageUploader теперь поддерживает multiple
<input
  type="file"
  accept="image/jpeg,image/png,image/webp,image/avif"
  multiple={true}  // ← Добавлено!
  onChange={handleFileSelect}
/>

// Правильная обработка массива файлов
const handleFileSelect = async (files: FileList | null) => {
  if (!files || files.length === 0) return;
  
  // Загружаем ВСЕ файлы и получаем результаты
  const fileArray = Array.from(files);
  const results = await uploadImages(fileArray);
  
  // Используем batch callback для атомарного добавления
  if (onUploadBatch && results.length > 0) {
    onUploadBatch(results);  // ← Один вызов со всеми фото!
  }
};

// В CreateRouteWizard.tsx
<ImageGalleryUploader
  images={stop.photos || []}
  onAddBatch={(imgs) =>
    onChange({
      photos: [...(stop.photos || []), ...imgs],  // ← Все сразу!
    })
  }
/>
```

**Что было не так (Race Condition):**
```typescript
// ❌ НЕПРАВИЛЬНО - race condition
results.forEach((image) => {
  onAdd(image);  // Вызов 1: photos = [...[], img1] = [img1]
                 // Вызов 2: photos = [...[], img2] = [img2]  ← читает старое []
                 // Вызов 3: photos = [...[], img3] = [img3]  ← читает старое []
});
// Результат: сохраняется только последнее фото [img3]

// Проблема: каждый onAdd читает старое состояние stop.photos
// React не успевает обновить состояние между вызовами
```

**Правильное решение:**
```typescript
// ✅ ПРАВИЛЬНО - batch update
onAddBatch(results);  // Один вызов: photos = [...[], ...imgs] = [img1, img2, img3]
// Результат: все фото сохранены!
```

**Преимущества:**
- ✅ Можно выбрать 5-10 фото за один раз
- ✅ Быстрее добавлять фотографии к точкам маршрута
- ✅ **Все выбранные фото сохраняются** (исправлена race condition)
- ✅ Атомарное обновление состояния (без промежуточных состояний)
- ✅ Улучшенный UX при работе с галереей
- ✅ Работает как с выбором файлов, так и с drag & drop

**Ограничения:**
- Максимум 10 изображений на точку (контролируется в ImageGalleryUploader)
- Каждое изображение загружается последовательно
- Показывается прогресс для текущего файла

**Техническая архитектура:**
1. `useImageUpload.uploadImages()` - загружает массив файлов
2. `ImageUploader.onUploadBatch()` - batch callback для результатов
3. `ImageGalleryUploader.onAddBatch()` - batch добавление в галерею
4. `CreateRouteWizard` - атомарное обновление `photos` массива

**Почему это важно:**
- React batch updates не гарантированы для async callbacks
- `forEach` с sync callbacks создает race condition
- Один `setState` с полным массивом = атомарная операция

### 6. Галерея фотографий для точек маршрута

Добавлена поддержка отображения **нескольких фотографий** для каждой точки маршрута с красивой галереей и модальным окном для просмотра.

**UI компоненты:**

```typescript
// Показываем первые 3 фото в сетке
<div className="grid grid-cols-3 gap-1">
  {displayPhotos.map((photo, idx) => (
    <div onClick={() => onPhotoClick(photos, idx)}>
      <img src={photo} />
      {/* На 3-й фотке показываем +N если фото больше 3 */}
      {idx === 2 && remainingCount > 0 && (
        <div className="absolute inset-0 bg-black/60">
          <span className="text-white text-lg font-bold">
            +{remainingCount}
          </span>
        </div>
      )}
    </div>
  ))}
</div>
```

**Модальное окно для просмотра:**
- Полноэкранный просмотр всех фотографий
- Навигация стрелками (← →)
- Индикатор текущего фото (точки внизу)
- Закрытие по клику на крестик
- Черный фон с прозрачностью

**Логика отображения:**
1. **1 фото** → показывается во всю ширину (aspect-ratio 4:3)
2. **2-3 фото** → сетка из 3 колонок, квадратные превью
3. **4+ фото** → первые 3 превью + на третьей "+N" оверлей

**Пример:**
```
[фото1] [фото2] [фото3]  ← 3 фото: все показаны
                  +2

[фото1] [фото2] [фото3]  ← 5 фото: показаны первые 3, 
                  +2     на третьей "+2" (еще 2 фото)
```

**Клик на фото:**
- Открывается модальное окно
- Начинается с кликнутого фото
- Можно листать все фото стрелками

**Обратная совместимость:**
- Поддерживает как новый формат `photos: string[]`
- Так и старый `photoUrl: string`
- Автоматическое определение какой формат использовать

### 8. Создание API эндпоинта для удаления маршрутов

Добавлен новый эндпоинт `DELETE /api/routes/[id]`:

```typescript
// src/app/api/routes/[id]/route.ts

export async function DELETE(
  request: NextRequest,
  { params }: { params: { id: string } },
) {
  const user = await getCurrentUser();
  
  if (!user) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  const route = await prisma.route.findUnique({
    where: { id: params.id },
    select: { id: true, authorId: true, title: true },
  });

  if (!route) {
    return NextResponse.json({ error: "Route not found" }, { status: 404 });
  }

  // Только автор может удалить свой маршрут
  if (route.authorId !== user.id) {
    return NextResponse.json(
      { error: "You can only delete your own routes" },
      { status: 403 },
    );
  }

  // Удаление с каскадным удалением связанных данных
  await prisma.route.delete({ where: { id: params.id } });

  return NextResponse.json({ success: true });
}
```

**Особенности:**
- Проверка авторизации пользователя
- Проверка прав доступа (только автор может удалить)
- Каскадное удаление связанных записей:
  - `RouteStop` (остановки маршрута)
  - `RouteSlugHistory` (история slug)
  - `RouteIdea` (сохраненные маршруты в "Идеи")
  - `PlanItem` (элементы плана)

## Результат

Теперь пользователь может:

1. **Сохранить черновик на шаге 1** - с базовой информацией (название, возраст, бюджет) без остановок
2. **Сохранить черновик на шаге 2** - с частично заполненными остановками (минимум 1)
3. **Опубликовать маршрут** - только если есть минимум 2 остановки

## Логика работы

### Черновик (Draft)
- Требуется только название
- Остановки опциональны (может быть 0, 1 или больше)
- Статус: `DRAFT`
- Доступен в разделе "Мои маршруты"

### Публикация (Publish)
- Требуется название
- Требуется минимум 2 остановки
- Каждая остановка должна иметь:
  - Адрес/местоположение
  - Для GOOGLE/MANUAL_PIN источников: customTitle
- Статус: `PUBLISHED`
- Виден в публичном каталоге
