# Redirect / legacy URL audit — summary

Source: `scripts/data/wp-redirect-map.json` (893 rows) → `manifest.csv` (893
redirect rows, generated by `pnpm build-migration-manifest`) → consumed by
`next.config.ts` via `src/lib/seo/redirectManifest.ts` at build time.

Two independent checks were run, answering two different questions.

## 1. Redirect rule validity (structural — what `next.config.ts` actually uses)

Ran `loadRedirectManifest()` (the exact function `next.config.ts` calls)
against the real `manifest.csv`:

```
total redirect rows: 893
valid rules produced: 893
issues: 0
```

Zero bad paths, zero trailing-slash destinations, zero self-redirects, zero
duplicate-source conflicts, zero unknown-destination-section, zero cycles.
`toPath()` extracts only the `pathname` from each `old_url`/`new_url` via
`new URL(url).pathname`, so the stale `http://mamago.local:3000` origin
baked into `manifest.csv` at generation time is discarded before it ever
becomes a redirect destination — not a bug.

**Redirect architecture: 893/893 structurally valid, 0 loops, 0 chains, 0
collisions.**

## 2. Destination content resolution (does the target exist & is it published today)

Ran `scripts/validate-redirect-map.ts` (extended with the disposition
classification below) against the local dev DB:

```json
{
  "EXACT_REDIRECT": 12,
  "VALID_HUB_REMAP": 21,
  "P1_START_OR_CONTAINS": 24,
  "INVALID_TARGET": 836,
  "COLLISION": 0,
  "CHAIN": 0,
  "LOOP": 0
}
```

- **EXACT_REDIRECT** (12): `type` ∈ {article, event, place, breakingnews},
  destination resolves to a real PUBLISHED entity.
- **VALID_HUB_REMAP** (21): `type` ∈ {event-category, place-category,
  place}, destination resolves to a live hub/listing page
  (`/minsk`, `/minsk/events`, `/minsk/birthday`, …) — precise 1:1
  taxonomy→hub mappings.
- **P1_START_OR_CONTAINS** (24): `type` ∈ {age, specialists, scenarios,
  hb-programs, uslugi, master-classes-fest, age-events} — loose
  best-effort category remaps (staff pages, seasonal campaigns, service
  pages) to a live hub. Lower content fidelity than VALID_HUB_REMAP, but
  destination is live and correct.
- **INVALID_TARGET** (836 — 121 Article, 715 Activity/event): the
  destination path is well-formed and matches the new URL scheme, but no
  live entity exists at that slug. This is the expected shape of the
  migration scope, not a redirect-config bug: only ~26 Articles and 10
  Activity/Event lineage records were ever migrated (see
  `prelaunch-checklist.md` §2), against 106 Article-type and 717 event-type
  rows in the legacy manifest. The great majority of these are historical/
  expired WP content that was deliberately excluded from migration (63
  events classified `P1_HISTORICAL_EXPIRED_ACTIVITY`, per the Users/
  Activities closure sessions). Following one of these redirects lands a
  real visitor on a real 404 for content that genuinely doesn't exist on
  the new site — correct behavior, not a defect. Per explicit instruction,
  not blocking release; the actual confirmed count (893) is the fixed
  baseline, not chased toward the old 900 target.
- **COLLISION / CHAIN / LOOP**: 0 each, confirmed by both the structural
  validator and the DB-resolution classifier independently.

## 3. Format warnings (15, non-blocking)

15 sources contain raw Cyrillic/`ў`/uppercase characters
(`/events/festival-Wostrau-Nesvizh-Fest`, `/events/kupalle-ў-festyvalnym`,
…) — cosmetic WP-era artifacts on `event`-type rows that are already
`INVALID_TARGET` for content-resolution purposes. Not blocking.

## 4. App-route collision check

One source, `/places`, matches a reserved top-level app segment
(`KNOWN_ROOT_SEGMENTS` in `wpLegacyCatchAll.ts`). Checked: no
`src/app/(public)/places/page.tsx` exists (only `places/[slug]/page.tsx`),
so `/places` is not a live route today — the redirect to `/minsk` fills
what would otherwise be a 404, it does not hijack a working page.
Separately flagged: `src/components/place/premium/PlaceHero.tsx` links to
`href="/places"` internally, which currently has no dedicated destination
page — noted for the internal-links audit (not a redirect-manifest issue).

## Tooling

## Verdict

Redirect architecture: **PASS** — 0 loops, 0 chains, 0 collisions, 0
duplicate sources, manifest structurally 100% valid. Content-resolution
