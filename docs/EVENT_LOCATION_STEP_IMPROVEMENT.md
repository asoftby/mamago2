# Улучшение шага "Локация" в визарде событий

## Обзор

Улучшен UX шага "Локация" в форме создания/редактирования события. Создан единый сценарий выбора локации через поиск существующих мест и быстрое создание новых, без дублирования элементов интерфейса.

## Что было сохранено

✅ Все ключевые блоки и функциональность:
- Блок "Мои места" - быстрый доступ к местам пользователя
- Блок "Особые случаи" - выездное событие и "локация будет объявлена"
- Вся бизнес-логика работы с координатами, районами и метро
- Механика карты и геолокации (переиспользуется в QuickPlaceCreate)

## Что удалено

❌ Дублирующий блок:
- Старый блок "Адрес или название места" с EventLocationPicker
- Причина: создавал два источника ввода и дублировал новый поиск

## Что добавлено

### 1. Единый основной контрол "Найти или создать место"

**Главный вход в сценарий выбора локации:**
- Поле поиска с placeholder "Начни вводить название места или адрес"
- Автокомплит с результатами из базы
- Опция "Создать новое место" в конце списка
- Визуальная индикация выбранного места (зеленая карточка)

- GET endpoint для поиска мест по названию или адресу
- Приоритизирует места пользователя
- Возвращает до 10 результатов с полной информацией
- Поддерживает поиск как по своим, так и по публичным местам

### 3. Компонент поиска мест
**Файл:** `src/components/business/wizard/event/steps/location/PlaceSearchAutocomplete.tsx`

Функциональность:
- Автокомплит с debounce (300ms)
- Поиск начинается с 2 символов
- Показывает результаты с иконками (свои места / публичные)

- Визуальное выделение выбранного места
- **Передает текущий query в callback `onCreateNew(initialName)` для автоподстановки**

### 4. Компонент быстрого создания места

Функциональность:

- Минимальные поля: название + адрес/карта

- Переиспользует EventLocationSearchInput и EventLocationMapModal

- После создания автоматически выбирает новое место
- Обновляет список "Мои места"

## Как это работает

### Единый сценарий выбора локации

**Главный вход:** Поле "Найти или создать место"

**Путь 1: Поиск существующего места**
1. Пользователь начинает вводить название или адрес
2. Появляется dropdown с результатами из базы
3. Результаты показывают: название, адрес, город, район/метро
4. Свои места выделены значком "Моё место"
5. Пользователь выбирает место → оно подставляется со всеми данными
6. Показывается зеленая карточка с подтверждением

**Путь 2: Создание нового места**
1. Пользователь вводит запрос, например "Экопарк Акварель"
2. Нажимает "Создать новое место" в dropdown
3. Открывается inline форма с полями:
   - Название места (обязательно) - **автоматически заполнено значением из поиска**
   - Адрес через автокомплит Google Places (обязательно) - **курсор автоматически переведен сюда**
   - Или выбор точки на карте
4. Пользователь заполняет адрес и нажимает "Создать место"
5. Место создается как DRAFT через API
6. Новое место автоматически выбирается для события
7. Список "Мои места" обновляется

**Путь 3: Использование "Моих мест"**
- Блок "Мои места" работает параллельно с поиском
- Можно выбрать место кликом по карточке
- Или найти через поиск - оба способа равнозначны

**Путь 4: Особые случаи**
- "Выездное событие" и "Локация будет объявлена" работают как раньше
- При выборе особого случая обычная локация сбрасывается
- Логика взаимоисключения сохранена

## Архитектура

### Автоподстановка названия места

**Как работает flow:**

1. **PlaceSearchAutocomplete** - при выборе "Создать новое место":
   - Вызывает `onCreateNew(query.trim())`
   - Передает текущий query как параметр

2. **Step2Location** - обрабатывает открытие формы:
   - Сохраняет `initialName` в состояние `quickCreateInitialName`
   - Вызывает `handleOpenQuickCreate(initialName)`
   - Устанавливает `showQuickCreate = true`

3. **QuickPlaceCreate** - получает и использует initialName:
   - Принимает `initialName` через props
   - Инициализирует поле "Название места" значением `initialName`
   - Создает ref `addressInputRef` для поля адреса
   - В `useEffect` устанавливает фокус на поле адреса (задержка 100ms)

4. **EventLocationSearchInput** - поддерживает автофокус:
   - Обернут в `forwardRef` для проброса ref
   - Использует `useImperativeHandle` для экспорта input элемента
   - Родитель может вызвать `.focus()` на ref

**Синхронизация состояния:**
- Search query используется как initial seed для названия места
- После открытия формы поле "Название места" редактируется независимо
- При закрытии и повторном открытии используется актуальный query
- Нет жесткой двусторонней синхронизации на каждый символ

**Edge cases:**
- Пустой query → поле "Название места" пустое
- Повторное открытие → берется актуальный query из search input
- Изменение названия в форме → не влияет на search input

### Переиспользование компонентов

**В QuickPlaceCreate используются:**
- `EventLocationSearchInput` - для ввода адреса с Google Places (обернут в forwardRef для автофокуса)
- `EventLocationMapModal` - для выбора точки на карте
- Вся логика геолокации и координат

**Удалено:**
- `EventLocationPicker` - больше не используется на шаге
- Причина: дублировал функциональность нового поиска

### Переиспользование API

- `/api/business/places` (POST) - для создания места
- `/api/business/places/for-events` (GET) - для загрузки "Моих мест"
- `/api/business/places/search` (GET) - новый endpoint для поиска

### Совместимость с данными

- Использует те же поля EventFormData
- Сохраняет совместимость с `venueKind`, `locationSource`, `placeId`
- Корректно работает с district/metro enrichment
- Поддерживает все существующие статусы и режимы

## Преимущества нового UX

1. **Один вход** - единое поле для всех сценариев выбора места
2. **Нет дублирования** - убран конфликтующий блок ввода адреса
3. **Быстрее** - не нужно уходить в раздел "Места"
4. **Понятнее** - очевидный путь: ввёл → выбрал или создал
5. **Гибче** - можно использовать поиск, "Мои места" или создать новое
6. **Безопаснее** - сохранена вся существующая логика
7. **Автоподстановка** - название из поиска автоматически подставляется в форму создания
8. **Автофокус** - курсор сразу переводится на следующее поле (адрес)

- Цветовая индикация: зеленый для выбранного, primary для своих мест

- Плавные анимации и transitions
- Responsive дизайн

- Переключение между режимами (поиск ↔ создание)
- Выбор особого случая при наличии выбранного места

- Клик вне dropdown
- Редактирование существующего события с локацией
