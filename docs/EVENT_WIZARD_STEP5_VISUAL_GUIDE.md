## Примеры сценариев

### Сценарий 1: Бесплатный концерт

```
Стоимость: [Бесплатно] ✓
Участие: [Только информация] ✓
CTA: [Подробнее] ✓

→ Результат: Простая карточка события
```

### Сценарий 2: Мастер-класс с простой записью

```
Стоимость: [Фиксированная цена] ✓ → 50 BYN
Участие: [Простая запись] ✓
  ├─ Дата: 2026-03-20
  ├─ Время: 14:00–16:00
  └─ Лимит: 15 человек
CTA: [Записаться] ✓

→ Результат: Форма записи с датой/временем
```

### Сценарий 3: Курс со слотами

```
Стоимость: [Цена "от"] ✓ → 30 BYN
Участие: [Запись по времени] ✓
  └─ Schedule Editor:
      ├─ 20 марта: 10:00-12:00 (10 мест), 14:00-16:00 (10 мест)
      ├─ 22 марта: 10:00-12:00 (10 мест)
      └─ 25 марта: 14:00-16:00 (10 мест)
CTA: [Записаться] ✓

→ Результат: Виджет выбора даты + слота
```

### Сценарий 4: Концерт с внешней продажей

```
Стоимость: [Фиксированная цена] ✓ → 100 BYN
Участие: [Покупка билета по ссылке] ✓
  └─ Ссылка: https://tickets.example.com
CTA: [Купить билет] ✓

→ Результат: Кнопка перехода на внешний сайт
```

### Сценарий 5: Индивидуальная консультация

```
Стоимость: [По запросу] ✓
Участие: [Оставить заявку] ✓
CTA: [Оставить заявку] ✓

→ Результат: Форма заявки
```

## Progressive Disclosure

### Уровень 1: Базовый выбор
```
Стоимость: 4 кнопки
Участие: 5 опций
CTA: 4 кнопки
```

### Уровень 2: Детали (показываются условно)
```
IF pricingMode = fixed/from
  → показать поле цены

IF participationMode = simple-booking
  → показать синий блок с датой/временем/лимитом

IF participationMode = time-slots
  → показать фиолетовый блок со Schedule Editor

IF participationMode = external-link
  → показать зеленый блок с полем ссылки

IF participationMode = request
  → показать желтый блок с helper text
```

## Color Coding

```
🔵 Simple Booking    → bg-blue-50 border-blue-200
🟣 Time Slots        → bg-purple-50 border-purple-200
🟢 External Link     → bg-green-50 border-green-200
🟡 Request           → bg-yellow-50 border-yellow-200
```

## Валидация

### Обязательные поля

```
✓ pricingMode (всегда)
✓ price (если fixed/from)
✓ participationMode (всегда)
✓ ticketLink (если external-link)
✓ simpleBookingDate (если simple-booking)
✓ timeSlots с датами и слотами (если time-slots)
✓ ctaType (всегда)
```

## Ключевые улучшения

1. **Прогрессивное раскрытие** - показываем только нужное
2. **Понятный язык** - без технического жаргона
3. **Визуальная иерархия** - цветные блоки для деталей
4. **Helper text** - объясняем механику каждого режима
5. **Гибкость** - от простого до продвинутого
6. **Единообразие** - одна форма для всех типов событий

## Итог

Новый Step 5 превращает примитивную форму в мощный, но понятный конфигуратор взаимодействия с пользователями.
