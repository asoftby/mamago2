# mamaGo Email Design System — этап 1

## Что является источником истины

- Фирменные токены: `src/features/email/components/email-theme.ts` (цвета синхронизированы с `src/app/globals.css`).
- Общая email-safe разметка: `src/features/email/components/email-layout.tsx`.
- Общая CTA-кнопка: `src/features/email/components/email-button.tsx`.
- Эталонный шаблон: `emails/mamago-welcome.tsx`.
- Текущий транспорт: `src/features/email/server/email-service.tsx` (Resend).

Верстка основана на React Email и таблицах; все стили inline. Используйте только поддерживаемые email-клиентами свойства. Ширина письма ограничена 600 px; мобильная область должна помещаться в viewport 390 px без горизонтальной прокрутки.

## Как менять текст без деплоя

Админка: **Коммуникации → Сценарии → WELCOME_EMAIL → Шаблоны → EMAIL**.

- `subject` меняет тему реального письма.
- `body` меняет вступительный абзац; HTML-теги удаляются при вставке в фирменный шаблон.
- Имя получателя подставляется из `userName` (по умолчанию просто «Привет!»).
- CTA «Собрать первый план» ведёт на `/me/plan` в соответствующем окружении. Текст кнопки и блок из трёх шагов редактируются кодом, не из админки.

Важно: этот механизм использует таблицу `NotificationTemplate` и scenario override. Запись с `EmailTemplate` из Email Studio **пока не участвует** в реальных welcome-отправках. Публикация в Email Studio сама по себе не изменит письмо пользователя.

## Локальный предпросмотр

В корне нового worktree с установленными зависимостями:

```sh
pnpm email:preview
```

Открыть `http://localhost:3011`, выбрать `mamago-welcome`.

Тест рендеринга (включён в `check:push`):

```sh
pnpm test:email-welcome
```

Проверить как минимум Apple Mail, Gmail web/mobile, Outlook desktop, отсутствие горизонтального скролла на 390 px, кликабельность CTA и безопасное отображение имён.

## Продолжение

1. Доработать Email Studio для выбора готового code-first дизайна и редактирования разрешённых полей, без произвольного HTML/CSS.
2. Подключить опубликованные неизменяемые версии к реальным сценариям отправки через единую точку разрешения шаблона. При отсутствии конфигурации использовать безопасный React Email fallback.
3. Добавить кодовые композиции для подтверждения записи, напоминания о плане, персональных подборок. Данные брать из server-side payload без раскрытия приватного семейного плана посторонним.
4. Вынести централизованную настройку логотипа/стилей, email-preheader и CTA-текстов, не создавая параллельную систему рассылок.

Ни одна отправка, деплой или изменение PROD-БД не требуется для этапа 1.
