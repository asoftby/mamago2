# Onboarding Integration - Complete ✅

## Проблема
После регистрации (ввод email и пароля) модальное окно оставалось открытым, не было шагов для ввода данных пользователя, интересов и детей.

## Решение
Интегрирована система onboarding flow после успешной регистрации.

## Изменения

### 1. Создан wrapper компонент `AuthWithOnboarding`
**Файл**: `src/components/auth/AuthWithOnboarding.tsx`

Этот компонент:
- Оборачивает `SiteAuthModal`
- После успешной регистрации закрывает auth modal
- Загружает данные пользователя
- Показывает `OnboardingFlow` modal
- После завершения onboarding делает редирект

### 2. Изменен `EmailLoginForm`
**Файл**: `src/app/(auth)/login/EmailLoginForm.tsx`

Изменение:
- После успешной регистрации НЕ делается редирект
- Вызывается `onSuccess()` callback
- Редирект происходит после onboarding

### 3. Обновлен `SiteAuthModal`
**Файл**: `src/components/auth/SiteAuthModal.tsx`

Изменения:
- Добавлен prop `user?: User | null`
- Добавлен import `OnboardingFlow`

### 4. Создан API endpoint `/api/auth/me`
**Файл**: `src/app/api/auth/me/route.ts`

Endpoint для получения текущего пользователя после регистрации.

### 5. Исправлен API endpoint `/api/user/onboarding`
**Файл**: `src/app/api/user/onboarding/route.ts`

Изменения:

### 6. Обновлены компоненты использующие auth modal

**Файл**: `src/components/site/header/HeaderAccountMenu.tsx`

## Как это работает

### Поток регистрации:

1. **Пользователь открывает auth modal**
   - Нажимает на иконку профиля
   - Или на кнопку "Мой план"

2. **Переключается на режим "Регистрация"**
   - Вводит email и пароль
   - Нажимает кнопку "Регистрация"

3. **Регистрация завершается**
   - API `/api/auth/complete-registration` создает аккаунт
   - НЕ происходит редирект
   - Вызывается `onSuccess()` callback

4. **Auth modal закрывается**
   - `AuthWithOnboarding` получает callback
   - Закрывает auth modal

5. **Загружаются данные пользователя**
   - Запрос к `/api/auth/me`
   - Получаем свежие данные User

6. **Открывается Onboarding modal**
   - Показывается `OnboardingFlow` компонент
   - Режим: `soft` (можно пропустить)

7. **Пользователь заполняет данные**
   - Шаг 1: Кто вы? (родитель/бизнес)
   - Шаг 2: Ваше имя
   - Шаг 3: Количество детей
   - Шаг 4: Интересы (опционально)

8. **Onboarding завершается**
   - Данные сохраняются через `/api/user/onboarding`
   - Onboarding modal закрывается
   - Происходит редирект на целевую страницу

### Альтернативный путь (Skip):

Пользователь может пропустить onboarding:
- Нажимает кнопку "Пропустить"
- Onboarding modal закрывается
- Происходит редирект на целевую страницу
- Onboarding можно пройти позже в профиле

## Onboarding Steps

### Родитель (Parent):
1. `use_case` - Выбор: родитель или бизнес
2. `adult` - Имя пользователя
3. `child` - Количество детей
4. `interests` - Интересы (опционально)
5. `completion` - Завершение

### Бизнес (Business):
1. `use_case` - Выбор: родитель или бизнес
2. `business` - Название, тип, город, контакт
3. `completion` - Завершение

## Режимы Onboarding

### Soft Mode (текущий)
- Все шаги опциональны
- Можно пропустить в любой момент
- Используется для регистрации через профиль

### Plan Required Mode (для будущего)
- Минимальные обязательные шаги
- Нельзя пропустить
- Используется для "Мой план"

### Deferred Mode (для будущего)
- Показывается после основного действия
- Можно отклонить
- Используется для сохранения событий
