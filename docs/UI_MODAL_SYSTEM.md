# Modal design system — mamaGo

Дата: 2026-10-10. Визуальный референс: полноэкранный мобильный поиск
(`MobileSearchSheet`), с центрированным заголовком, крестиком справа,
прокручиваемым содержимым и закреплёнными нижними действиями.

## Два слоя, не две конкурирующие системы

- `Dialog` / `Sheet` (`src/components/ui`) — Radix-примитивы: focus,
  клавиатура, dismissible, backdrop, доступность.
- `ResponsiveOverlay` (`src/components/ui/responsive-overlay.tsx`) —
  уже существующий адаптивный контейнер (desktop dialog / mobile sheet).
  Сохраняем и развиваем его, не вводим второй `AppModal`.
- `ModalHeader`, `ModalFooter`, `ModalPrimaryAction`
  (`src/components/ui/modal-chrome.tsx`) — общие **визуальные элементы**.
  `MobileOverlayResetAction` — уже существующее вторичное действие для
  фильтров. Их можно применять в Radix-шите, диалоге или в кастомном
  fullscreen-поиске без изменения логики.

## Семантика действий

| Контекст | Слева | Справа |
| --- | --- | --- |
| Поиск / фильтры | Сбросить (лишь когда уместно) | Показать / Готово |
| Форма добавления | Опционально: Отмена | Добавить |
| Форма редактирования | Опционально: Отмена | Сохранить |
| Подтверждение удаления | Отмена | Удалить (destructive, НЕ primary orange) |
| Информационная модалка | — | Понятно либо вовсе без футера |
| Галерея / просмотр / истории | — | — |

`ModalHeader` получает `SheetTitle` или `DialogTitle` как `title`,
если используется внутри Radix. Крестик — `onClose`; отключён по умолчанию
лишь в сценариях, где закрытие должно быть запрещено. `ModalFooter` —
оболочка, **без зашитой логики reset/apply**. Сохраняйте проверку
несохранённых данных и доступность там, где она уже есть.

## Phase 1 (эта ветка)

- `MobileSearchSheet`: chrome вынесен в общие элементы, логика фильтров,
  guided-flow, baseline и автоприменение не меняются.
- `MobileFilterSheet`: центрированный заголовок + крестик; нижние
  действия используют общие стили; `onReset`/`onDone` прежние.
- `MobileSelectSheet`: тот же заголовок и действия; `onSelect`,
  `onClear`, single/multi и вложенные шиты сохраняются.
- Проверка контракта: `pnpm test:responsive-public-overlay`,
  включая `modal-chrome.test.tsx`.

### Специальные UI, которые НЕ перерисовываем

- **`SaveToPlanModal` («Добавить в план»): визуально и функционально
  одобрен владельцем продукта. Не изменять ради унификации.**
- `MyPlanOverlay` (собственный drag handle), `StoryModal`,
  gallery/lightbox, `BreakingNewsModal` — их предназначение требует
  отдельной композиции, не обязательного footer.
- Auth/onboarding/опасные подтверждения — только после аудита
  dismissible, ошибок, keyboard, подтверждений.

## Дальнейшая миграция

1. После проверки Phase 1: `MobileDateSheet`, простые form-модалки
   (профиль, заметки), другие фильтры. Переносить по одному семейству.
2. Общий внешний вид для админки и B2B — отдельный PR после аудита
   больших редакторов, таблиц и вложенных диалогов.
3. После подтверждения отсутствия usages удалять legacy-разметку.
   Не менять `Dialog`/`Sheet` глобально ради скриншота.

### QA перед merge

Проверить на 320px / 375px / 768px / desktop: центр заголовка,
крестик, back/ESC/backdrop, фокус и табуляцию, вложенные шиты,
состояния кнопок, прокрутку длинного контента, safe-area на iOS,
сохранение фильтров и reset. Отдельный smoke «Добавить в план» без
визуальных изменений. PR не мерджить без зелёных проверок.
