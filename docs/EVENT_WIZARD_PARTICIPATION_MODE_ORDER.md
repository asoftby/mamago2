# Event Wizard - Participation Mode Order Update

## Обзор

Изменен порядок вариантов `participationMode` в Event Wizard Step 5 для отражения реальной логики выбора бизнеса.

## Проблема

Старый порядок не отражал логику выбора:
1. Только информация (пассивное)
2. Простая запись
3. Запись по времени
4. Покупка по ссылке
5. Оставить заявку

Это не соответствовало тому, как бизнес думает о взаимодействии с пользователями.

## Решение

Новый порядок идет от наиболее активного взаимодействия к наименее активному:

1. **Покупка билета по ссылке** - максимальное взаимодействие (покупка)
2. **Запись по времени (слоты)** - активное взаимодействие с выбором времени
3. **Простая запись** - стандартное взаимодействие (заявка)
4. **Оставить заявку** - минимальное взаимодействие (запрос)
5. **Только информация** - пассивное (без взаимодействия)

## Логика нового порядка

### От активного к пассивному

```
Высокая активность
    ↓
1. external-link    → Покупка (транзакция)
2. time-slots       → Выбор времени + запись
3. simple-booking   → Простая заявка
4. request          → Запрос информации
5. info-only        → Только просмотр
    ↓
Низкая активность
```

### Бизнес-логика

1. **Покупка билета** - если есть готовый продукт для продажи
2. **Слоты** - если нужно управление временем и capacity
3. **Простая запись** - стандартный сценарий для большинства событий
4. **Заявка** - если нужна предварительная консультация
5. **Только инфо** - для анонсов без взаимодействия

## Преимущества нового порядка

### 1. Соответствие бизнес-логике
Бизнес думает о взаимодействии от "максимального" к "минимальному":
- Сначала рассматривают продажу
- Потом запись
- В конце - просто информация

### 2. Лучший UX для бизнеса
- Наиболее коммерческие опции сверху
- Пассивные опции внизу
- Дефолт = наиболее распространенный сценарий

### 3. Логическая группировка
```
Коммерческие:
  - Покупка билета

Booking:
  - Слоты
  - Простая запись

Информационные:
  - Заявка
  - Только инфо
```

### 4. Оптимизация выбора
- Большинство событий = "Простая запись" (теперь дефолт)
- Коммерческие события видят "Покупку" первой
- "Только информация" не мешает активным сценариям

## Статистика использования (гипотеза)

```
Ожидаемое распределение:
─────────────────────────────────
simple-booking    → 60%  (дефолт)
time-slots        → 20%
external-link     → 10%
request           → 5%
info-only         → 5%
```

Новый порядок оптимизирован под это распределение.
