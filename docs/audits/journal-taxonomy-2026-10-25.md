# Аудит таксономии журнала — 25.10.2026

## Подтверждено по репозиторию
- Канонические разделы уже реализованы как `/[city]/blog/category/[category]`. Переименовывать URL нельзя без SEO-аудита и редиректов.
- Категории публикаций: `EventCategory` с `publicationType=ARTICLE`, `slug`, `nameRu`, `sortOrder`, `parentId`, `isActive`. Текстовые SEO-поля категории в схеме отсутствуют.
- Статья может попадать в категорию как по `categoryId`, так и через `ArticleCategoryLink`.
- Метка «Статья» используется как fallback интерфейса, если у публикации нет категории. Само по себе это **не доказывает** наличие категории «Статья» в БД.
- Sitemap уже содержит непустые индексируемые страницы категорий по существующим URL.

## Не проверено: нужна read-only выборка из PROD
У этой сессии нет соединения с PROD-БД. Поэтому **не приводим вымышленные цифры** по категориям и не утверждаем, что тестовые записи опубликованы.

Провести read-only проверку:
1. Выгрузить все активные и архивные категории `publicationType=ARTICLE` с `id, slug, nameRu, parentId, sortOrder, isActive`.
2. Для каждой категории посчитать уникальные опубликованные статьи с учётом основной и дополнительных связей, отдельно по Минску и национальным материалам.
3. Сопоставить ID опубликованных статей с объединением разделов навигации; вывести статьи без связи с доступным разделом (`id, slug, title, categoryId, publishedAt`).
4. Найти в PROD опубликованные материалы, где название похоже на `%тест%`, `%test%`, `%проверки вывода%` (проверить также описания и slug). Указать точные публичные URL и статус; **ничего не удалять**.
5. Проверить GSC и манифест редиректов по текущим `/blog/category/*` и потенциальным `/blog/*` перед любым изменением slug.

- Удалять тестовые записи.
- Переименовывать SEO slug или менять существующие разделы навигации по предположениям.
