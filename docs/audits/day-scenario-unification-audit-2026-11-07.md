## 8. Кластеризация и режимы передвижения (решения владельца от 2026-11-07)

Дополнение к ТЗ движка. Реализация — в составе PR 1, порядок прежний: после
закрытия RC1 #1103 и baseline на DEV.

**Предварительные факты** (по `schema.prisma` на `e6a9fcd90`, проверяются
аудитом п. 0):

- `Place.lat/lng` (`Float?`) и `Place.territoryId` есть; у `Activity` своих
  координат нет — только `placeId` (`Activity.placeId`), `territoryId` и
  `metroStationId` (у `MetroStation` есть `lat/lng`).
- `Territory` — иерархия **COUNTRY → REGION → CITY**; уровня «район» в ней нет.
  «Район» живёт в отдельной модели `District` (`cityId`, legacy `territoryId`
  указывает на город), а у `Place`/`Activity` ссылки на `District` нет. Поэтому
  «territoryId района» буквально взять неоткуда — см. вопрос в п. 0.
- Единственная реализация расстояний — `src/lib/geo/haversineMeters.ts`
  (+ `scenarioTravel.ts`, `listNearbyCities.ts`, `place-match-scorer.ts`);
  geohash и гео-индексов нет.

**Решения:**

0. **Аудит перед реализацией.** Какие гео-поля уже есть у `Place`/`Activity`
   (координаты, адрес, привязка к `Territory`/району), как `Activity` связано
   с местом проведения (в т.ч. онлайн / без места / несколько мест), есть ли
   geohash/гео-индексы и расчёты расстояний кроме `scenarioTravel.ts`.
   Переиспользуем и расширяем, не дублируем. **Короткий отчёт — в начале PR 1.**
   Открытый вопрос аудита: чем считать «район» при отсутствии района в
   `Territory` и ссылки на `District` у `Place`. Рабочее предложение — не
   заводить новую сущность, а считать «районом» окрестность `geoCell`
   (geohash-6 ≈ 1,2 × 0,6 км) + соседние ячейки, а `territoryId` оставить
   как грубый фильтр города/области. Решение фиксируется отчётом PR 1.
1. **Кластеры считаются при записи, не при сборке.**
   - `territoryId` + `geoCell` (geohash-6) для `Place` и `Activity`
     (у `Activity` — от места проведения);
   - проставлять при создании / обновлении / импорте; одноразовый бэкфилл
     существующих записей; аддитивная миграция — вручную (правила миграций
     репозитория: без `migrate dev`, без `db push`);
   - сущности без координат исключаются из пешего режима.
2. **Пул кандидатов в кэше** индексируется по `geoCell` и `territoryId`;
   соседние ячейки находятся вычислением, без запросов в БД. Пересборка в
   пределах TTL остаётся без обращений к БД.
3. **Сборка:** якорь (точное время или лучший скоринг) → кандидаты со штрафом
   за удалённость от якоря и от предыдущей точки; сила штрафа зависит от
   режима.
4. **Режим «Пешком»** (жёсткие ограничения):
   - только та же и соседние `geoCell`; переход ≤ 15 мин (~1,2 км), иначе точку
     не ставим;
   - сумма за день ≤ 3 км (с ребёнком 0–3 — ≤ 2 км); один район; цепочка без
     возвратов;
   - если кандидатов не хватает — состояние «Рядом мало вариантов —
     переключиться на машину?».
5. **Режим «Машина»** (гибкие ограничения):
   - весь город, предпочтение того же/соседних районов; переход предпочтительно
     ≤ 25 мин, > 40 мин — предупреждение «Далеко — заменить?»;
   - максимум один дальний переезд за день; штраф растёт с суммарным временем
     в пути; порядок точек — без петель.
6. **Режим «Транспорт»** — промежуточные коэффициенты, в UI пока скрыт.
7. **Выбор «Пешком / Машина» возвращается в UI**: переключатель в черновике,
   значение сохраняется в профиле семьи; дефолт — машина. Это осознанное
   отклонение от макета «просто» (правило подписи из раздела 5 — «на машине»,
   «пешком» при переходе до 15 мин — остаётся: подпись показывает фактический
   режим перехода).
8. **Время в пути** — по-прежнему haversine-оценка + кэш `TravelEstimate`,
   без внешних API.

**Следствия для PR 1 / рисков:**

- Новые колонки `geoCell` (+ индекс) и, возможно, `territoryId` у `Activity`
  нужны вместе с бэкфиллом; при каждой записи `Place` (создание, правка
  координат, импорт, `resolvePendingLocationOnPublish`) `geoCell` должен
  пересчитываться — иначе кластеры разъедутся. Покрыть тестом на каждый путь
  записи, найденный аудитом п. 0.
- Профиль семьи получает поле режима передвижения (аддитивная миграция,
  nullable, дефолт «машина» на чтении).
- Пеший режим — единственный режим с жёсткими «нет точки»: нужен явный
  результат движка «мало вариантов» (а не пустой сценарий), чтобы UI показал
  переключение на машину без повторной сборки вслепую.
- Модель `TravelEstimate` (раздел 7) хранит режим в ключе
  `(fromPlaceId, toPlaceId, mode)`; для 0–3 лет лимит 2 км применяется на
  уровне сборки, а не в кэше расстояний.
