# Birthday A4

The Offer wizard stores travel and delivery city IDs in Offer.details.serviceAreas. Both lists reference existing active CITY territories. Only the list appropriate to the offer's current category and fulfilment mode is used. An empty list supplies no geographic evidence.

The interval pricing adapter reuses the reservation duration and price calculators. For an exact-price offer with a documented booking duration, it compares a complete booking base with an explicitly matching public fixed-duration price. Extensions require an available resource over the full interval including both buffers and a configured full-hour rate. This is read evidence. Confirmation keeps the existing transaction and database exclusion constraint. A fixed variant can carry validated partyConditions on its existing Offer.priceItems row. The selector checks the Minsk date and time, duration, guest count, age evidence and exact mandatory component IDs before comparing amounts. Existing unqualified price items and class group tariffs do not establish applicability to a birthday and remain unresolved. Conditional prices are available to the candidate pipeline. The existing draft snapshot and accepted quote remain separate from the candidate estimate.

Package edits through the offer create and update APIs share one transaction helper. Removing a draft component archives the row. The published composition guard still requires moderation. A4 snapshots each mandatory component on its order item, independently of its optional foreign key. Migration snapshots any still-linked legacy component as it exists at migration time. Category-only orders retain the included rows already stored in the order. Missing historic titles and item prices cannot be reconstructed. The accepted PartyQuote and the price stored on the confirmed PartyOrderItem remain the agreed price. The component snapshot's catalog price fields are provenance and do not change that amount.
