- Система `BookingRequest` поддерживает `NEW/CONFIRMED/COMPLETED/REJECTED`; «выполнено» в бизнесе само по себе не является двусторонним подтверждением.
- `src/server/services/userBirthdays.service.ts` пока отдаёт `MOCK_PARTY_DETAIL`.

## Решения продукта (согласованы)
- mamaGo — маркетплейс, не координатор. Один праздник содержит площадку и услуги разных исполнителей.
- Для пилота: площадка + торт, для торта можно прикрепить референс и пожелания один раз.
- Запрос на площадку — первым; остальные только после её подтверждения.
- Для услуг-заданий система подбирает адресатов автоматически; мама выбирает исполнителя среди реальных откликов по цене/рейтингу/портфолио.
- Платёж напрямую исполнителю по его правилам, в том числе предоплата; единый платёж через mamaGo пока не реализуем.
- Комиссия mamaGo — 10% от согласованной конечной стоимости фактически выполненной услуги; факты спрашиваем у исполнителя и заказчика, расхождения — на ручную проверку.

- Комиссия 10% только на подтверждённую базу, без двойного начисления; спор и неответ — отдельные статусы, не автоматическое списание.
- Реестр для бухгалтерии, аудит изменений, выгрузка по исполнителям; оплата напрямую бизнесу.
- Юридически согласовать договор, акты, основания для расчёта комиссии и разрешение споров в Беларуси до выставления документов.

## Критерии выпуска
1. Создание и повторное редактирование `PARTY_SERVICE` и `PARTY_PACKAGE`: все поля сохраняются и читаются.
2. Услуги из состава пакета не дублируются при сборке.
3. Площадка получает настоящую заявку; торт — не раньше её подтверждения.
4. Любое подтверждение видно только после фактического ответа партнёра; никаких демо-цен и демо-статусов.
5. Отказ, просрочка, повторная отправка, смена исполнителя и отсутствие доступных кандидатов не ломают заказ.
6. Отдельные проверки прав доступа к заявке и фотографиям; мобайл UX.
