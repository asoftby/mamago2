# Изолированный каталог для приёмки праздников

Этот набор создаёт обычные Offer/PackageComponent/BookingUnit в отдельной локальной PostgreSQL. Production API, правила видимости и ценовой движок не меняются. Никакие данные не устанавливаются на DEV/PROD. Draft #1148 не объединяется; его пересечения с каталогом и A5 проверяются отдельно.

## Окружение и вход

Node 22.23.2, pnpm 10.28.2, PostgreSQL 16. Используйте изолированный checkout задачи с собственными зависимостями, подготовленный task-start. Не копируйте `.env*`: локальный runner откажется при наличии файлов, которые Next.js может прочитать.

Единственный разрешённый адрес БД — `127.0.0.1:55443/mamago_birthday_it`. Ни `APP_ENV=dev`, ни подтверждение флагом не разрешают другой адрес. ENV/URL проверяются до загрузки Prisma. Параметры URL, кроме `schema=public`, запрещены, включая переопределение host.

```sh
export PATH="$HOME/.nvm/versions/node/v22.23.2/bin:$PATH"
export APP_ENV=local
export BIRTHDAY_DEMO_LOCAL=1
export DATABASE_URL='postgresql://party_it_runner@127.0.0.1:55443/mamago_birthday_it?schema=public'
```

Если отдельная БД уже поднята, используйте её и не повторяйте initdb/migrations. Для первого запуска на macOS (проверьте, что порт свободен):

```sh
BIRTHDAY_PG_BIN=/opt/homebrew/opt/postgresql@16/bin
BIRTHDAY_PG_ROOT=$(mktemp -d /private/tmp/mamago-birthday-demo.XXXXXX)
LC_ALL=en_US.UTF-8 "$BIRTHDAY_PG_BIN/initdb" -D "$BIRTHDAY_PG_ROOT/data" -U party_it_runner -A trust -E UTF8
LC_ALL=en_US.UTF-8 "$BIRTHDAY_PG_BIN/pg_ctl" -D "$BIRTHDAY_PG_ROOT/data" -o '-p 55443 -c listen_addresses=127.0.0.1' -l "$BIRTHDAY_PG_ROOT/server.log" -w start
"$BIRTHDAY_PG_BIN/createdb" -h 127.0.0.1 -p 55443 -U party_it_runner mamago_birthday_it
pnpm exec prisma migrate deploy
```

`migrate dev`, `migrate reset` и пакетные скрипты reset запрещены. Этот PR не добавляет миграций.

```sh
pnpm birthday:demo seed
pnpm birthday:demo:start
```

Откройте `http://127.0.0.1:34357/minsk/birthday/make`. Локальный server runner наследует только PATH/HOME/TMPDIR и проверенный DATABASE_URL; почтовые, SMS, Telegram, AI и cloud credentials ему не передаются. Сервер слушает только loopback. Существующие confirmation/inbox/Family Core флаги включены только в его изолированном процессе. Это не изменение deployment-конфигурации и не обход ACL/availability. Не запускайте worker/cron с реальными transport credentials.

Пароль **всех синтетических аккаунтов**: `BirthdayDemo!2026`. Адреса `.test` не являются реальными получателями.

| Вход | Роль |
| --- | --- |
| `parent@birthday-demo.test` | Владелец первой семьи |
| `adult@birthday-demo.test` | Второй взрослый той же семьи |
| `outsider@birthday-demo.test` | Владелец другой семьи |
| `owner-1@birthday-demo.test` | Бизнес 1 |
| `owner-2@birthday-demo.test` | Бизнес 2 |
| `owner-3@birthday-demo.test` | Бизнес 3 |

В семьях существуют два Child-профиля возрастом 8 и 6 лет; фиктивные детские User-аккаунты не создаются. Seed не выдаёт семье доступ к заказу автоматически: завершение этой интеграции относится к следующему PR.

## Данные и воспроизведение

ID имеют префикс `birthday-demo-v1-`; точный inventory — `scripts/it/birthdayDemo/catalog.ts`. Создаются 37 предложений: 30 самостоятельных услуг (по три в каждой из десяти категорий), 5 пакетов, один снятый с публикации DRAFT и один исполнитель другого города. В публичном минском API видны 35. Варианты 1/2 каждой категории принадлежат разным бизнесам и совместимы с обычным праздником восьмилетнего ребёнка. Вариант 3 проверяет более старший возраст, вместимость, бюджет и формат. Отсутствие фотографии отображается честным штатным placeholder.

| Пакет | Цена и состав |
| --- | --- |
| `package-all` | EXACT 900; зал REQUIRED; аниматор FIXED_CREDIT 100; торт NO_REFUND; декор QUOTE_REQUIRED; фото FIXED_CREDIT 80 |
| `package-flex` | EXACT 500; программа NO_REFUND; отдельная опция с `isOptional=true` и REQUIRED; legacy-компонент без правила |
| `package-home` | FROM 350; выездной пакет; изменения HOME остаются безопасно заблокированными |
| `package-outdoor` | FROM 450; выездная программа/кейтеринг; изменения OUTDOOR остаются безопасно заблокированными |
| `package-custom` | ON_REQUEST; фиксированной базы и вымышленных уменьшений нет |

Архивный компонент `package-all-archived` не входит в новый заказ. Кредиты — явно заданные условия синтетических бизнесов; это не backfill и не правила реальных компаний. FREE представлены `show-3` и `other-3`; ON_REQUEST — `cake-3` и индивидуальный пакет.

Дата — через 14 дней по календарю Europe/Minsk; команда seed печатает её. В `unit-venue-1` занято 12:00–14:00 Минск, свободно 14:00–16:00. **Этот единственный ресурс совместно используют `venue-1` и `package-all`**: бронь любого из них исключает другой в том же интервале. Для `show-3` единственный ресурс INACTIVE. Расписания остальных ресурсов 09:00–21:00 во все дни; ограничения вместимости сохраняются.

Для проверки изменения каталожной цены сохраните пакет в PartyOrder, затем измените его цену через бизнес-визард: старый заказ должен сохранить snapshot. PG-тест воспроизводит 900 → 950 после сохранения заказа с кредитом 100 и проверяет прежнюю оценку 800.

Повторный seed не перезаписывает ручные изменения предложений, аккаунтов, правил и заказов. Он только добавляет недостающие fixture-записи и переносит собственный календарный block на относительную дату. Не используйте seed как reset.

## Очистка

```sh
pnpm birthday:demo cleanup
```

Требуются те же локальные ENV/URL. Удаляются только фиксированный inventory и принадлежащие синтетическим аккаунтам заказы/заявки. Это завершает их сессии. Общие City/Country/Territory сохраняются. Существующие IT-фикстуры `it-offer-*`, посторонние аккаунты и бизнесы не затрагиваются.

Очистка отказывается работать при чужих потребителях, дополнительных Offers на fixture-площадках, вручную созданных ресурсах демобизнеса, дополнительных площадках, созданных демопользователями или принадлежащих демобизнесам, и ссылках из других семей/планов. Сначала явно разберите такие связи. Ошибка не должна приводить к частичному удалению: проверки и удаления выполняются в одной транзакции. Повторная очистка безопасна. Не запускайте интеграционный тест во время ручной приёмки: он проверяет cleanup/reseed и отзывает текущие тестовые сессии.

## Проверки и дисциплина gate

```sh
pnpm test:birthday-demo
pnpm exec eslint scripts/it/birthday-demo*.ts scripts/it/birthdayDemo/*.ts
pnpm test:birthday-demo:integration
```

Последняя команда требует описанного изолированного ENV и тестирует настоящие записи/видимость, пароли, Family Core, занятость общего ресурса, замороженные цены, повторный seed, отказ cleanup при чужих связях и ручном контенте, повторную очистку и последующий seed. В конце каталог снова готов для ручной приёмки. Существующий Birthday DB workflow запускает её последовательно после своих тестов в той же отдельной БД; параллельных потребителей этой БД не добавлено.

В быстрых циклах запускаются только затронутые unit/PG/ESLint. Полный gate — после конечного commit через task-finish; task-check перед ним не запускается. Успех повторно используется только штатным exact-SHA proof. Итоговые SHA, gate и CI фиксируются в PR, не в самоподтверждающем тесте. Корневой tsconfig исключает scripts: поэтому `test:birthday-demo` дополнительно запускает отдельный узкий TypeScript project для этих файлов; проверка включена и в gate, и в CI. Глобальный TypeScript требует `NODE_OPTIONS=--max-old-space-size=6144`; стандартный heap в этой задаче завершился OOM и не считается PASS.

Runtime маршруты не меняются: новый seed не добавляет запросов, polling или веток выдачи для тестовых карточек. Число/размер записей ограничены inventory. Данные проходят обычные visibility/compatibility/price services.

См. `demo-catalog-acceptance.md` для фактической приёмки и известных ограничений. Полная цепочка бронирования, финальный семейный сценарий и публичная ссылка проверяются в следующих отдельных PR; этот каталог не объявляет их готовыми.
