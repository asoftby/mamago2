# ТЗ 3. Экран «Записи» в бизнес-кабинете (business.mamago.by)

**Прототип:** `bookings-prototype.html` (артефакт «Записи mamaGo Business») — эталон состава, поведения и текстов. Визуал — текущий фирстиль кабинета (чёрные активные чипы, скругления, «сегодня» синим).
**Зависимости:** ТЗ 2 §2b–2c, §3 (`BookingRequest`, `BookingAllocation`, HELD/истечение, статусы FULL/PARTIAL). До фазы 3 экран работает на текущих `BookingRequest` без колонок исполнителей.
**Ограничения:** как в TZ-0 (PROD не трогать, аддитивные миграции, не дублировать механизм блокировок, мобильный 360 px, светлая и тёмная тема).

---

## 1. Что не так сейчас

- Первый экран занимают 5 KPI-плиток («Новых / Ожидают ответа / Подтверждённых / Завершённых / Отменённых» с нулями). Главное действие бизнеса — ответить на заявку — ниже сгиба.
- Дата фильтруется трижды: полоса дней, чипы «Все даты / Сегодня / Завтра», пустое поле с иконкой календаря без подписи.
- Вкладки статусов обрезаются на мобильном («Подтверждённы…»).
- Есть «записи дня», но нет **занятости**: не видно, что свободно, что держится под заявкой, что закрыто, у какого исполнителя.
- Нельзя закрыть время или добавить запись по телефону.

## 2. Структура экрана (сверху вниз)

1. **Строка-сводка** вместо плиток: «Ждут ответа N» (акцентом, если N > 0) · «На неделе N» · «Выручка недели X BYN». Полные счётчики по статусам — в чипах списка (п. 5).
2. **«Ждут ответа»** — карточки заявок `NEW` и `PARTIAL`, по сроку ответа:
   - клиент · дата, время · сумма; предложение · детей;
   - для `PARTIAL` — жёлтая карточка и строка конфликта («⚠ Аниматор Маша не работает в пятницу»);
   - таймер «Ответьте до … — иначе время освободится» (= `holdUntil`);
   - главная кнопка: «Подтвердить» (или для PARTIAL «Подтвердить без <услуги> −N BYN»), вторая — «Подробнее».
   - Пусто: «Все заявки отвечены. Новые появятся здесь первыми.»
3. **Неделя:** 7 дней, стрелки ‹ ›. На дне: точки статусов (новая / почти подходит / подтверждена / вручную) и полоса загрузки основного ресурса. «Сегодня» — синяя рамка, выбранный — чёрный. Нерабочий по расписанию или закрытый день — приглушён. **Один** способ выбора даты; чипы «Сегодня/Завтра» и поле даты убрать.
4. **Переключатель «По исполнителям | Список».**
5. **По исполнителям (по умолчанию):** вертикальная шкала времени, колонки = ресурсы (`BookingUnit`) бизнеса: Зал / Маша / Олег, в шапке колонки — часы работы ресурса в этот день.
   - Нерабочее время ресурса — штриховка.
   - Блоки: ждёт ответа (пунктир, акцент), почти подходит (пунктир, жёлтый, на колонке конфликтного ресурса «⚠ не работает»), подтверждена (заливка), вручную (серый), закрыто (красная штриховка). После блока — штриховка уборки (`bufferMin`).
   - Одна бронь праздника = блоки во всех колонках своих ресурсов (из `BookingAllocation`), каждый — на своё время.
   - Тап по блоку → карточка записи (п. 6). Тап по пустому месту → «Что сделать с этим временем?» (п. 7), время округляется до 30 мин.
   - Заголовок дня: «Суббота, 17 октября · 3 записи · зал занят на 55%». Закрытый день: «День закрыт в расписании. Изменить — в предложении, шаг „Расписание“».
6. **Список:** чипы-фильтры с счётчиками (Активные · Ждут ответа · Подтверждённые · Состоялись · Отменённые), горизонтальная прокрутка без обрезки. Строка: дата/время · клиент и предложение · детей, сумма, конфликт · статус-пилюля.

## 3. Карточка записи (нижняя шторка)

- Статус-пилюля, «Клиент · дата, время», предложение и источник (онлайн-запись / почти подходит / отдельная услуга / вручную).
- Таймер ответа (для NEW/PARTIAL).
- PARTIAL: жёлтый блок с причиной и тем, что клиент оставил заявку, понимая это.
- Детей, сумма, состав (снимок из заявки, ТЗ 2 §2a), комментарий клиента.
- «Кто и когда занят»: ресурс → интервал (+ уборка).
- **Контакт:** до подтверждения номер маскирован (`+375 33 ••• •• 02`) + «Написать в mamaGo»; после подтверждения — полный номер, выделяемый текстом, и «Копировать» (с фолбэком на выделение). Проверить соответствие правилам депозита/доступа к лидам из модели монетизации.
- Действия по статусу:
  | Статус | Действия |
  |---|---|
  | NEW | Подтвердить · Предложить другое время · Отклонить |
  | PARTIAL | Подтвердить без <услуги> −N · Подтвердить как есть — договорюсь · Предложить другое время · Отклонить |
  | CONFIRMED | Перенести · Отменить запись |
  | MANUAL | Перенести · Удалить запись |
  | COMPLETED / CANCELLED | только просмотр (+ причина отмены) |
- История: создана, подтверждена, перенесена, отменена — с временем.
- «Подтвердить без <услуги>»: убирает услугу из состава, пересчитывает сумму через `quoteOffer`, снимает её HELD-allocation, остальные HELD → CONFIRMED; клиенту — уведомление с новой суммой.
- «Предложить другое время»: клиенту уходит ссылка на выбор времени по `getStartTimes` для того же состава; исходная заявка держится до ответа клиента или истечения.

## 4. Закрыть время / запись по телефону

Шторка из тапа по пустому месту или кнопки «📅+ Запись» справа от заголовка дня (и над списком). **«+» в шапке кабинета не трогаем** — он создаёт новую публикацию (событие, место, предложение) и к записям не относится.
- переключатель «Закрыть время | Запись по телефону»;
- С / До (предзаполнено), для закрытия — причина; для записи — имя, детей, телефон;
- подпись: «Это время сразу пропадёт на сайте у всех предложений, где участвует «<ресурс>», и в конструкторе праздников»;
- создаёт `BookingAllocation` (тип `MANUAL_BLOCK` или ручная бронь) на ресурс — через тот же exclusion constraint; при конфликте — понятная ошибка «Это время уже занято: <кто>».
- Открыть закрытое время — из его карточки («Открыть время»).

## 5. Уведомления

Колокольчик с точкой при наличии NEW/PARTIAL. Push/Telegram о новой заявке ведёт сразу в карточку записи. Напоминание за 2 часа до `holdUntil`.

## 6. Критерии готовности

- [ ] Первый экран на 390 px: сводка + первая заявка «Ждут ответа» с кнопкой «Подтвердить» видны без прокрутки.
- [ ] Один способ выбора даты; вкладки/чипы не обрезаются.
- [ ] День по исполнителям строится из `BookingAllocation` и часов ресурсов; бронь праздника видна во всех своих колонках.
- [ ] PARTIAL-заявка: подтверждение без услуги корректно пересчитывает сумму и снимает только блокировку этой услуги.
- [ ] Закрытие времени и ручная запись сразу убирают время из `getStartTimes` всех связанных предложений и конструктора (интеграционный тест).
- [ ] Номер клиента маскирован до подтверждения.
- [ ] Истёкший `holdUntil` освобождает время и переводит заявку в «Истекла» (отдельная пилюля в списке).
- [ ] Светлая и тёмная тема, 360–390 px без горизонтальной прокрутки.
